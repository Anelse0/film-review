# 本剧审阅档案：怎么建、怎么更新

## 它是什么

项目根目录的 `review-profile.md`（模板 `templates/review-profile.md`），一页纸：本剧怎么规定、哪里自由、用户说过什么。审阅第一步读它，相当于监制导演给客座导演交底。职业剧集靠成文的规则和常驻的人守住语法，问题也是语境相关的——不先读本剧的规则，就会拿通用审美去扣本剧刻意的选择。

档案是**派生文档**：规则正本在导演偏好文档和剧本规则表里。规则改了先改正本，再更新档案。档案只为审阅服务，不替代正本。

## 来源（按这个顺序读）

1. **导演偏好文档**（例如 `director-guide.md`）：记下版本行。
2. **剧本规则表**（例如 `story/rules.md`）：只取影响表演、调度、视点的条（情绪只渐进、公开场合不转折、人物先反应后处理之类）；只管台词和剧情的条不取。
3. **项目记忆**里和导演设计有关的条：镜头、表演、节奏、光、构图、审阅方式。
4. **成片证据**：film-director `references/validation-log.md` 里本项目的行，看"用户判定"。设计层的教训进档案；措辞与渲染的教训列进"写法规则"一节、标归 film-director。
5. **用户评价过的成片**：正面样例与反例，写清值得照学的、要避开的设计是什么。
6. **平台记录**（例如 `platform.md`）：只取影响设计的约束（画幅、首帧）。

## 分类

每条规则归入一类，拿不准时按用户原话的强度判：

- **硬规则**：用户说"一律 / 不要 / 禁用 / 必须"的，或因成片出错而定下的。违反 = 致命。
- **默认值**："默认 / 少用 / 优先"。偏离要写理由；没写理由 = 重要。
- **写法规则**：管措辞与渲染的（台词括号、手机握法、不写眼睛里的光、方向句）。只列名字，标归 film-director，审阅不计。
- **用户裁定**：用户对某条审阅意见说"不同意 / 就这样"的原话。之后同类意见不再提。

## 冲突表

对 `rubric.md` 的每个维度问一遍：本剧规则有没有改变它的判法？有就写一行"通用原则 | 本剧规则 | 审阅时怎么写"。只写会改变结论的，不抄规则全文。常见的几类：

- 本剧规定的默认运动和通用的"摄影机只在有理由时动"方向相反——动机要求保留，默认值翻转。
- 本剧锁死了某个参数（机位高度、构图位置、静默时长）——这个参数不再能编码含义，转到"被关掉的手段"。
- 本剧的布光是类型化的（魅力光）——不按"避免魅力光"扣分，但光源仍要有来处。
- 本剧锁定了台词——"删台词成全表演"一类通用解法不能用，只能用画面解，涉及台词的转剧本层。
- 本剧规定审阅方式（例如不派 subagent）——冷读改成同一审阅者的独立工序。

## 被关掉的手段

列出被本剧规则关掉的经典手段，和还允许的替代手段。这是审阅时最容易漏的一项：规则越多，方案越可能"守规矩但没有递进"。

## 文档内部冲突

来源文档之间、同一文档的新旧条款之间互相矛盾的：按较新的判，写明位置、版本和审阅时按哪条，列进档案最后一节交用户清理。不自己改正本。

## 更新

- 档案头写来源与版本：导演偏好文档版本号、剧本规则表更新日期、建档与更新日期、film-review 版本。
- 每次审阅前对一下导演偏好文档的版本行；变了就重读变更的条款（看它的版本记录），只改受影响的行。
- 用户在审阅后裁定的，提议写进"用户裁定"，等用户同意再写。
- 写档案是落盘：写完在回复里一句话说改了什么。
